| 12 | C04 · C05 | 가입 → C03 → C04 → C05를 차례로 그렸고, 시연 건너뛰기 자리가 없다 | **결정 0011**: 시연 계정은 동의를 끝낸 상태로 시드한다. 가입부터 보여 주는 흐름이면 시연 도구에서 `동의 완료`로 건너뛴다 | 직접 부딪치지는 않는다. 다만 C04를 다시 만들 때 대기 카드 아래의 시연 조작(`동의 완료로 건너뛰기`, 시연 도구 켜짐 + 목업 토큰일 때만)을 빠뜨리지 말 것. 시드 계정은 지금처럼 `AGREED` |
| 13 | C01 → C02 | 연결선이 로그인 → 역할 선택 | U-01 · API: 역할은 가입 때 한 번 정하고, `PATCH /users/me`로 바꿀 수 없다 | 로그인 뒤 역할 선택이 아니라 C01 `회원가입` → C01A → C02로 읽는다. 디자이너 확인 |
| 14 | C03 · C04 · C06 · C08 | 상단 바 `‹`, GNB 없음 | 지금은 로그인한 화면 모두에 역할 탭을 그린다(`RoleTabLayout`). 인증 전에도 홈 · 목록은 둘러볼 수 있다(기능 명세 T 머리말) | 인증 화면만 탭을 숨길지, `‹`이 어디로 가는지(가입 직후에는 돌아갈 곳이 없다) 정한다 |

## 시안에 없는 상태 (디자이너 요청 목록)

- **C01**: 로그인 실패 문구.
- **C01A · C02**: 비밀번호 확인 불일치, 필수 약관 미체크, 이메일 중복(409), 역할을 고른 카드 모양, 아무것도 안 고른 상태.
- **C03**: 사진을 고른 뒤 모양, 형식 · 용량 오류, **심사 중(PENDING)**.
- **C04**: 미요청 · 대기 · 거부 · 만료 · 동의 완료 다섯 상태의 카드 문구와, 대기 중 폼 숨김.
- **C05**: 동의 거부, 처리 뒤(동의 · 거부), 링크 만료 · 잘못된 링크, 체크 전 버튼 잠금.
- **C06**: 불일치 · 휴폐업 결과, 인증 완료.
- **C07**: 심사 중 · 반려 · 동의 대기 · 거부 · 만료, 가이드 변형(보호자 줄 없음 · 학교 · 학과), 사장님 변형(만든다면).

## 구현 크기 (제안)

S = 한 파일의 문구 · 배치. M = 라우트 · 상태 흐름이나 새 부품까지. L = 여러 화면 흐름을 다시 짬. 문구가 바뀌면 단위 · E2E 테스트 선택자도 함께 고친다(위 "공통" 표).

| 코드 | 크기 | 무엇 |
|---|---|---|
| C01 | S | 머리 · 칸 라벨 · 안내 상자 · 하단 버튼 · 텍스트 링크 |
| C01A + C02 | M | 두 단계 폼(값 보존, 마지막에 한 번 가입), `비밀번호 확인`, `Checkbox` 새 부품, 409를 1단계로 되돌림, 역할 카드 모양 |
| C03 | M | 고교생 · 가이드 두 페이지의 폼을 한 모양으로(학교 칸 유지), `StepList` · `Notice` · 하단 고정 |
| C04 | M | `/verify`에서 떼어 낸 새 라우트, 상태 카드, 시연 조작 옮기기, `getLandingPath` 수정 |
| C05 | S | 배지 카드 + 단계 목록 + 동의 체크로 버튼 잠금, 이름 가림. `동의하지 않기`는 유지 |
| C06 | S | 머리 · placeholder · 안내 · 버튼 문구. 개업일자 유지, 상호명은 결정에 따라 |
| C07 | M | 새 화면 + 라우트 둘(고교생 · 가이드), `StatusRow` 새 부품, MY 행 연결 |
| C08 | S | C03의 반려 변형(danger 안내 상자, 문구) |

C03 · C04 · C08과 첫 화면 규칙은 한 묶음으로 바꿔야 하므로 묶음 크기는 L이다. 공용 새 부품은 `Notice` · `Checkbox` · `StatusRow` · 배지 카드(선택형 포함) 넷이다.
