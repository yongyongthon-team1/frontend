- Task 5 완료: 첫 화면 · 신청 버튼 · 내 탐방 카드 · 쿠폰 · 학생 코스 라벨의 표시 상태 파생 함수와 단위 테스트를 만들었다.
- Task 6 완료: 목업 DB(ERD 19개 테이블 행 타입 · 오늘 기준 상대 날짜 시드 · localStorage 저장소 · 시계 · 거리 계산)와 시연 계정 설정을 만들었다.
- Task 7 완료: 목업 규칙(신청 · 승인 · 거절 · 취소, 정원 자동 마감 · 복구, 쿠폰 발급 · 만료 · 조회 · 사용)과 오류 코드별 단위 테스트를 만들었다.
- Task 8 완료: 목업 AI(관심사 추출 · 탐방 추천 · 코스 초안)와 코스 규칙(초안 · 순서 변경 · 한줄평 · 지점 삭제 · 확정과 쿠폰 발급 · 조회 권한), 체크포인트 시드(신청 · 승인 · 확정)를 만들었다. 결정 0008(코스 초안은 관련 후보 중 제휴 상점을 최소 1곳 포함)이 목업에 반영됐다.
- Task 9 완료: 계약 초안의 29개 엔드포인트를 모두 MSW 핸들러로 만들었다(응답 DTO 변환 · 목업 지연 · 도메인별 핸들러 선택). 앱은 목업 모드에서 렌더 전에 브라우저 목업 워커를 켜고, 시연 설정 저장소(최소판)를 두었다. 대시보드 API 연동표의 목업 열이 모두 ✅가 됐고, `frontend-needs.md` 6절에 재신청 규칙과 목업 AI 문구가 임시라는 점을 적었다.
- Task 10 완료: 디자인 토큰(`tokens.css`)을 Tailwind 4 테마로 연결하고 Pretendard를 npm으로 번들했다. 한글 조합 중 Enter 방지(`ime.ts`), 프레임 포털 컨텍스트, 공통 UI 컴포넌트 19개와 테스트를 만들었다. 결정 0003(모든 스타일 값은 토큰)이 반영됐고, 하이파이는 `tokens.css` 값 교체로 적용한다.
- Task 11 완료: 앱 셸(세션 토큰 보존 · `['me']` 쿼리 · 로그인/역할 가드 두 겹 · 폰 프레임 · 역할별 하단 탭)과 로그인 화면(hs-s01)을 만들고, 설계 5.3의 라우트를 모두 등록했다. 아직 없는 화면은 자리 화면이라 막다른 곳이 없다. 이후 화면 테스트는 같은 앱을 메모리 라우터로 그리는 `renderApp`을 쓴다.
- Task 12 완료: `vercel.json`(SPA rewrite)과 Playwright 설정을 만들고, 프로덕션 빌드(`vite preview`)에서 로그인 후 `/my-tours`를 새로고침해도 로그인 · 목업이 유지되는 E2E 스모크를 통과시켰다. Vercel 연결은 사용자 확인 대기라 체크포인트 "빈 앱 배포"는 🟨다.
- Task 13 완료: 고교생 홈(hs-s03, 관심사 문장 · 예시 칩 · 학교/학과/날짜 조건)과 AI 추천 목록(hs-s04)을 만들었다. 추천이 0건이면 같은 학교 → 전체 순으로 넓힌 목록과 안내 칩을 보여 주고(hs-a06 추천 쪽), 탐방 상세 쪽 예외는 Task 14에서 마무리한다. 하단 탭은 하위 화면(추천 목록 · 탐방 상세 등)에서도 켜진 채 유지된다(판정 11).
- Task 14 완료: 탐방 상세(hs-s05) · 신청서(hs-a04) · 신청 완료(hs-s06)와 신청 불가 상태(hs-a06: 정원 마감 · 인증 미완료 · 이미 신청 · 거절됨)를 만들었다. 신청 버튼은 `applyButtonState`가 정하고 비활성이면 사유 + 다음 행동 링크를 함께 보여 준다. 신청서는 앞뒤 공백을 자른 5~300자만 보내고 연타해도 요청은 한 번이며, 실패하면 토스트와 함께 탐방 정보를 다시 불러온다. 신청 API · 쿼리 훅(내 신청 · 취소 · 가이드 신청자 보드 · 승인/거절)도 함께 만들었다.
- Task 15 완료: 내 탐방 상태별 목록(hs-a05)과 상세(hs-s07: 오픈채팅 링크 · 코스 확정 시 지도/쿠폰 버튼 · 신청 취소)를 만들었다. 취소는 서버가 준 `cancellable`을 그려서 탐방 당일이면 비활성 + 사유가 보이고, 취소하면 쿠폰 만료 안내 확인창을 거친다. hs-a06의 다섯 번째 상태(탐방·신청 취소)도 이 취소 흐름으로 채워졌다.
- Task 16 완료: 탐방 코스 지도(hs-s08)를 만들었다. 카카오맵 SDK 로더는 키가 없거나 4초 안에 뜨지 않거나 `kakao.maps`가 없으면 도식 지도로 넘어가고(결정 0004), 핀이나 지점 카드를 누르면 상점 시트(추천 이유 · AI 리뷰 요약 · 별점 · 제휴 혜택 · 쿠폰 보기)가 열린다. 코스가 확정 전이거나 승인 전이면 "준비 중"을 보여 준다. 키가 아직 없어 목업 · 테스트는 도식 지도로 확인했다(팀 요청 16). 다음 태스크가 쓸 코스 API · 훅(가이드 초안 · 순서 · 한줄평 · 삭제 · 확정)과 쿠폰 API · 훅(내 쿠폰 · 5초 갱신 상세 · 사장님 조회 · 사용 처리)도 함께 만들었다.
- Task 17 완료: 쿠폰 목록과 상세(hs-s09)를 만들었다. 상세는 6자리 코드를 위쪽에 크게(`4 8 2 1 6 9`) 보여 주고, 아직 쓸 수 있는 쿠폰이면 5초마다 다시 불러와 사장님이 사용 처리하면 `사용 완료 · HH:mm`으로 바뀐다. 마지막으로 본 쿠폰은 시연 설정 저장소(`lastCoupon`)에 남긴다.
- Task 18 완료: 가이드 탐방 목록(guide-a02: 진행 중 탐방별 신청 · 승인 수와 신청자 보기 · 탐방 취소 링크, 지난 탐방 기록)과 신청자 관리(guide-s03: 요약 숫자, 승인 · 거절 확인창, 코스 버튼 상태)를 만들었다. 승인이나 거절 요청이 진행 중이면 모든 승인 · 거절 버튼이 잠겨 연타해도 요청은 한 번이고, 남은 자리가 없으면 승인은 사유와 함께 비활성이다.
- Task 19 완료: AI 코스 초안(guide-s04) · 편집(guide-s05: 순서 · 한줄평 · 삭제) · 확정(guide-s06: 승인 수와 쿠폰 발급 수)을 만들었다. 초안은 `?generate=1`이고 코스가 없을 때 한 번만 만들고(StrictMode에서도 요청 1번) 성공하면 주소에서 `?generate=1`을 지운다. 무대 화면 450px 제약에 맞춰 지점 카드를 위로 올렸고 1280×720에서 세 곳이 모두 보이는 것을 확인했다. 옛 추천 기준 문구는 실제 기준(`course.criteria`)으로 바뀌어 디자인 · 기획 공유만 남았다(팀 요청 10).
