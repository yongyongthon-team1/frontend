# 목업 상점 데이터 (용인시 소상공인 상가정보)

목업(MSW) 시드의 상점 590곳은 모두 공공데이터의 실제 가게다. **상호 · 업종 · 주소 · 행정동 · 좌표만 실데이터**이고, 상점 1~4의 제휴 조건 · 쿠폰 · 리뷰 · 별점 · AI 리뷰 요약과 사장님 계정(owner1~4)은 **시연용으로 지어낸 값**이다. 실제 가게의 혜택 · 평가가 아니다. 실서버는 백엔드가 같은 원본을 따로 적재한다.

화면의 출처 줄(`STORE_DATA_SOURCE`)은 `공공데이터(소상공인 상가정보) 기반`이다(2026-11-08까지는 `공공데이터(인허가) 기반`).

## 거른 조건

원본 한 행(상가업소번호 하나)을 아래를 모두 만족할 때만 남긴다.

1. 시군구명이 `용인시`로 시작(`용인시 처인구` · `용인시 기흥구` · `용인시 수지구`)
2. 상권업종대분류명이 `음식`
3. 상권업종중분류명이 `주점`이 아님 — 방문자가 고교생(미성년자)이다
4. WGS84 좌표(위도 · 경도, 소수점 7자리로 반올림)가 한국 범위(위도 33~39, 경도 124~132)이고, 시드의 대학 중심 다섯 곳 중 하나에서 1000m(`COURSE_RADIUS_M`) 안
5. 상가업소번호가 처음 나온 행(중복 제거)

결과: 590행. 대학별로 강남대 185 · 경희대 국제캠퍼스 106 · 단국대 죽전 185 · 명지대 자연 104 · 한국외대 글로벌 10. 반경 안의 주점 37행은 빠졌다.

행마다 남기는 칸: `sourceId`(상가업소번호) · `name`(상호명, 지점명이 있으면 한 칸 띄워 붙임 — 예: `스타벅스 죽전단국대`) · `category`(아래 대응표) · `industryMiddle` · `industryMinor`(원본 중 · 소분류) · `address`(도로명주소, 없으면 지번주소) · `district`(시군구명) · `administrativeDong`(행정동명) · `lat` · `lng` · `campusId`(가장 가까운 대학).

## 업종 대응표

원본 중분류 · 소분류를 앱 업종(`STORE_CATEGORIES`, `src/features/stores/model.ts`)으로 옮긴다. 소분류 표가 먼저이고, 없으면 중분류 표, 둘 다 없으면 `기타`다.

| 원본 | 앱 업종 |
|---|---|
| 소분류 `김밥/만두/분식` | 분식 |
| 소분류 `버거` · `피자` · `토스트/샌드위치/샐러드` | 양식 |
| 소분류 `빵/도넛` · `아이스크림/빙수` | 카페 (코스 초안의 `카페` 의도에 `디저트`가 있다) |
| 중분류 `한식` | 한식 |
| 중분류 `중식` | 중식 |
| 중분류 `일식` | 일식 |
| 중분류 `서양식` | 양식 |
| 중분류 `비알코올` | 카페 |
| 그 밖(`동남아시아` · `구내식당·뷔페` · 기타 간이의 `치킨` · `떡/한과` · `그 외 기타 간이 음식점`) | 기타 |

상가정보는 음식점만 거르므로 `보드게임카페` · `노래방` · `공방`(코스 초안의 `놀거리` 업종) 상점은 없다. 놀거리 의도는 관심사에만 남고 지점은 생기지 않는다.

## 시드에서 쓰는 법

`src/mocks/db/seed.ts`가 `src/mocks/db/data/yonginStores.json`을 읽는다. 상점 id는 이렇다.

| id | 상호 (업종) | 주소 | 역할 |
|---|---|---|---|
| 1 | 렌토 (양식) | 경기도 용인시 기흥구 서천동로43번길 5-10 | 제휴 · owner1 · 리뷰 5개 · 코스 초안의 식사 지점 |
| 2 | 타임리스커피 (카페) | 경기도 용인시 기흥구 서천동로43번길 11-9 | 제휴 · owner2 · 리뷰 5개 · 코스 초안의 카페 지점 |
| 3 | 땡큐꼬마김밥 (분식) | 경기도 용인시 기흥구 서천서로12번길 4-18 | 제휴 · owner3 |
| 4 | 모모식당 (한식) | 경기도 용인시 기흥구 서천서로12번길 8-20 | 제휴 · owner4 |
| 5 | 단 (한식) | 경기도 용인시 수지구 죽전로144번길 15-4 | 단국대 근처 비제휴 |
| 6 | 일삼일구 (카페) | 경기도 용인시 수지구 죽전로144번길 15-14 | 단국대 근처 비제휴 · 사장님 가게 찾기 · 연결 시연 대상(연결 전) |
| 7~590 | 나머지 실데이터 584곳 | — | 대학 → 상가업소번호 순. 사장님 · 제휴 · 리뷰 없음 |

1~6은 `DEMO_STORE_SOURCE_IDS`(상가업소번호)로 고른다. 1 · 2는 코스 초안 규칙(반경 1km 안 · 캠퍼스 밖 · 관련 업종에서 대학 중심과 가장 가까운 상점, 제휴 여부는 순위에 쓰지 않음)으로 경희대 탐방에서 실제로 뽑히는 식사 · 카페 상점이라 시연 코스(예술·디자인대학 → 렌토 → 타임리스커피)가 그대로 나온다. 캠퍼스 안 매장(주소가 대학 주소와 같은 행 — 경희대는 14곳이 대학 주소로 지오코딩된 2m 간격의 두 좌표, 중심에서 186 · 188m에 모여 있다)은 코스 초안의 상점 후보에서 빠지고, 주변 상점 · 검색 · 장소 고르기에는 나온다.

## 다시 만드는 법

원본 CSV는 저장소에 없다. 공공데이터포털 15083033에서 전국 파일을 내려받아 경기 CSV 경로를 넘긴다(기준 연월은 파일 이름 끝 `_YYYYMM.csv`에서 읽는다).

```sh
node scripts/build-yongin-stores.mjs "<내려받은 폴더>/소상공인시장진흥공단_상가(상권)정보_경기_202609.csv"
npx vitest run src/mocks/db/data src/mocks/db/seed.test.ts src/mocks/ai
```

- 의존성 없는 Node 스크립트이고 같은 입력이면 같은 파일을 쓴다(정렬: 대학 → 상가업소번호).
- 대학 중심 좌표는 스크립트의 `CAMPUSES`와 `createSeed`가 같아야 한다. 데이터 테스트(`yonginStores.test.ts`)가 모든 행이 시드 대학 중심 1km 안 · 용인시 · 주점 없음 · 상가업소번호 중복 없음 · 대응표대로인지 본다.
- 기준 연월이 바뀌면 시연 상점 1~6의 상가업소번호가 그대로 있는지, 코스 초안이 여전히 1 · 2를 고르는지 테스트로 확인하고 `MOCK_DB_VERSION`을 올린다. 행 수가 바뀌면 상점 id(7번부터)를 쓰는 테스트 기대값도 바뀐다.
