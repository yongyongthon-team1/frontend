- Task 18 완료: 가이드 탐방 목록(guide-a02: 진행 중 탐방별 신청 · 승인 수와 신청자 보기 · 탐방 취소 링크, 지난 탐방 기록)과 신청자 관리(guide-s03: 요약 숫자, 승인 · 거절 확인창, 코스 버튼 상태)를 만들었다. 승인이나 거절 요청이 진행 중이면 모든 승인 · 거절 버튼이 잠겨 연타해도 요청은 한 번이고, 남은 자리가 없으면 승인은 사유와 함께 비활성이다.
- Task 19 완료: AI 코스 초안(guide-s04) · 편집(guide-s05: 순서 · 한줄평 · 삭제) · 확정(guide-s06: 승인 수와 쿠폰 발급 수)을 만들었다. 초안은 `?generate=1`이고 코스가 없을 때 한 번만 만들고(StrictMode에서도, 생성 중에 화면을 떠났다 돌아와도 요청 1번) 성공하면 주소에서 `?generate=1`을 지운다. 무대 화면 제약(판정 28: TopBar와 하단 탭 사이 약 400px)에 맞춰 지점 카드를 위로 올리고, 위쪽 칩은 작은 AI 배지로, 관심사는 가로 스크롤 한 줄로, 지점 카드는 66px로 줄였다. 판정 28의 무대 뷰포트(1366×620 · 1280×600 · 1280×590 @1.5배)에서 세 번째 지점 카드가 하단 탭 위에 들어오는 것을 확인했다(TopBar 아래로 393px, 여유 46 · 26 · 16px). 옛 추천 기준 문구는 실제 기준(`course.criteria`)으로 바뀌어 디자인 · 기획 공유만 남았다(팀 요청 10).
- Task 20 완료: 사장님 쿠폰 사용 처리(owner-s03 · owner-a03)를 만들었다. 6자리 코드를 넣으면 조회하고(`?code=`로 미리 채움, 시연 도구가 켜져 있으면 최근 쿠폰 채우기), 서버가 사용 가능(USABLE)이라고 한 쿠폰만 사용 처리 버튼이 켜지며 연타해도 요청은 한 번이다. 이미 사용 · 만료/다른 가게 · 없는 코드 · 당일 전 오류는 문구를 정하는 순수 함수(`couponNotice`)로 카드를 그리고, 성공하면 "이번 탐방으로 온 학생 N명"을 보여 준다.
- Task 21 완료: 시연 도구를 만들었다. 프레임 옆 시연 패널(폭 900px 미만이면 프레임 오른쪽 위 토글 뒤에 접힘)에서 역할 4개 빠른 전환, `쿠폰 가게 사장님으로 전환`(학생이 마지막으로 본 쿠폰 코드를 사용 처리 화면에 채움), 체크포인트 골라 시연 데이터 초기화, API 모드 표시 · 전환, 백엔드 상태(15초 확인), 지도 도식 고정, 목업 AI 느리게, 발표 모드를 다룬다. 발표 모드에서는 패널이 역할 버튼 막대로 줄고 프레임 오른쪽 위에 `가이드 화면` 같은 역할 배지가 뜬다. 원클릭 링크(`/?demo=1&reset=1&as=student&present=1`)는 초기화와 로그인을 첫 렌더 전에 끝낸다. 역할 전환은 로그인이 끝난 뒤 캐시 비우기 · 새 신원 · 이동을 한 번의 렌더로 바꿔, 로그인 화면이 끼지 않고 이전 역할의 데이터도 보이지 않는다(Review Focus 4 · 판정 31). 빠른 로그인한 시연 계정은 세션이 끊기면(401) 한 번 자동으로 다시 로그인한다. 결정 0007에 목업 쪽 초기화 · 체크포인트 · 원클릭 링크를 적었다.
- Task 22 완료: 배포 빌드(목업 · AI 속도 보통)에서 시연 골든 패스 E2E를 끝까지 통과시켰다. 원클릭 링크로 시작해 시연 패널로 역할을 바꾸며 고교생 추천 · 신청 → 가이드 승인 · AI 코스 초안 · 순서 변경 · 확정(쿠폰 발급) → 고교생 코스 지도 · 쿠폰 코드 → 사장님 사용 처리까지 돈다. 페이지 오류나 실패한 API 요청이 하나라도 있으면 실패한다. 무대 해상도 점검(판정 28 뷰포트 1366×620 · 1280×600 · 1280×590 @1.5배)에서는 관심 키워드 · 첫 추천 이유, 코스 초안 지점 3곳, 쿠폰 코드가 스크롤 없이 하단 탭 위에 보인다. TopBar 아래로 각각 370 · 393 · 344.5px을 쓰고, 가장 작은 뷰포트에서 39 · 16 · 64.5px이 남아 화면 배치는 바꾸지 않았다. 설계 5.7의 무대 예산을 450px에서 400px로 고쳤고, README에 실행 · 테스트 · E2E 명령, 환경변수, 시연 계정, 원클릭 시연 링크, 문서 위치를 정리했다. 이것으로 MVP 1단계(기반 + 시연 골든 패스) 계획 22개 태스크가 끝났다.
- 최종 리뷰 수정 완료(판정 32~35): README 무대 링크의 발표 모드에서 세로 막대만으로 골든 패스를 끝까지 돈다(`사장님` = 학생이 마지막으로 본 쿠폰의 가게 사장님 + 코드 채움, `present=1` 골든 패스 E2E 추가). 초기화는 최근 쿠폰을 지우고 세션 토큰 없이 부르며, `reset=1`은 AI 속도 · 지도도 기본값으로 되돌리고, 막대에는 API 모드와 기본값이 아닌 설정이 보인다. 역할 배지를 16px 굵게 키웠고(골든 패스 제목을 덮지 않음), 승인 · 거절 실패 때 신청자 보드를 다시 불러오고, 학생 화면 6개가 재조회 실패에도 데이터를 유지하고, 화면 단위 에러 경계로 화면이 깨져도 하단 탭 · 시연 패널이 남는다. 캐시 무효화 공백 3곳, 가이드 목록 정렬, FrameContext 위치, 파비콘, 테스트 토스트 정리를 고쳤고, 계약에 시연 전제(계정 · 같은 비밀번호 · 가게 ↔ 사장님 · 체크포인트 · 리셋 약속)와 최근 리뷰 필드(`CourseStop.review.recent`, 화면은 2단계)를 넣었다.
