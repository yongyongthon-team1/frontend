# 0007. 시연 데이터는 시드한 당일 날짜로 만든다

- 날짜: 2026-11-03

## 맥락

탐방 신청 취소 가능 여부와 쿠폰 사용 가능 여부는 날짜에 따라 달라진다. 시연이 11/15인데 데이터가 과거 날짜면 쿠폰이 만료되고, 시계를 조작하면 서버와 목업이 어긋난다. 사용자가 본선 시연은 실서버가 기본이고 목업은 대비용이라고 정했다(추천안 선택).

## 결정

시연 탐방은 "오늘", 시작 시각은 발표 시간대 이후, 제휴 기간은 오늘을 포함하도록 시드를 실행한 날 기준 상대 날짜로 넣는다. 서버와 목업 모두 시계를 조작하지 않는다. 발표에서는 "탐방 당일로 설정한 시연 데이터"라고 밝힌다. 실서버가 기본이고, 발표 10분 전 백엔드와 LLM 상태를 보고 한 번만 모드를 정한 뒤 시연 중엔 바꾸지 않는다. 백엔드에는 시드 스크립트와 비밀 키로 보호한 시연 리셋 수단을 요청한다(팀 요청 13번).

## 결과

시연 직전에 시드를 한 번 실행하면 쿠폰이 "사용 가능" 상태로 시작한다. 프론트는 자기 시계로 유효 여부를 판단하지 않고 서버가 준 값(`Coupon.state`, `MyApplication.cancellable`)을 그린다. 시연 패널의 "시연 데이터 초기화"는 목업이면 시드 복원, 실서버면 리셋 수단을 호출한다.

## 구현

2026-11-04, Task 9 · Task 21. 목업 쪽을 먼저 만들었다. 실서버 쪽은 백엔드 리셋 수단(팀 요청 13번)이 오면 같은 호출로 붙는다.

- 목업 시드는 시드한 날(Asia/Seoul) 기준이고, 저장된 DB의 시드 날이 오늘이 아니면 버리고 다시 시드한다. `POST /api/demo/reset { checkpoint? }`은 오늘 기준 시드로 되돌린다. 체크포인트는 골든 패스를 그 단계까지 진행한 시드다: `START`(처음) · `APPLIED`(신청 완료) · `APPROVED`(승인 완료) · `CONFIRMED`(코스 확정, 쿠폰 발급). 목업은 `X-Demo-Key`를 보지 않는다(403은 실서버 전용).
- 시연 패널의 `시연 데이터 초기화`는 고른 체크포인트로 위 API를 부른다. 초기화 키가 있으면 헤더 `X-Demo-Key`로 보낸다. 성공하면 세션 토큰 · 빠른 로그인 기록 · 쿼리 캐시를 비우므로, 발표자는 역할 버튼으로 다시 들어간다.
- 원클릭 시연 링크 하나로 시연을 세팅한다. 예: `/?demo=1&reset=1&checkpoint=CONFIRMED&as=student&present=1`. `demo=1`은 시연 도구를 켜고, `mode=mock|real`은 API 모드를 저장하고, `reset=1`과 `checkpoint`는 초기화하고, `as=student|guide|owner|admin`은 그 역할로 빠른 로그인하고, `present=1`(끄기는 `present=0`)은 발표 모드이고, `key`는 실서버 초기화 키다. 초기화와 빠른 로그인은 첫 렌더 전에 끝내 로그인 화면이 깜빡이지 않는다. 처리한 파라미터는 주소에서 지우고 `present`만 남긴다. 실패하면 토스트를 띄우고 앱은 그대로 그린다.
- 빠른 로그인 비밀번호는 로그인 요청을 목업이 받으면 시드 비밀번호(`DEMO_SEED_PASSWORD`), 실서버가 받으면 env `VITE_DEMO_PASSWORD`다. 빠른 로그인한 시연 계정의 요청이 401이면 페이지 세션당 한 번 같은 계정으로 다시 로그인한다. 백엔드 재시작이나 모드 전환 뒤에도 시연이 끊기지 않게 하려는 것이다.
