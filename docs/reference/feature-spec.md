# 기능 명세 (스냅샷)

> 원본: 노션 `기능 명세` — https://app.notion.com/p/409e0c1995d68043a6b5c9dbfbe9b91f
> 스냅샷: 2026-11-03. **정본은 노션이다.** 이 파일은 개발 참고용 사본이며 원본이 바뀌면 다시 옮긴다.
> 하위 문서 `기능 명세 변경 정리` 내용은 맨 아래에 함께 옮겼다.

한 행이 기능 하나이고, 접두어가 같은 기능은 내일 같은 API 리소스로 묶는다. 모든 기능은 user-flow 탭의 단계 하나 이상에 연결된다.
처리 규칙은 형식적으로 적어두기는 했으나, 구현 도중 변경 가능.

## T 탐방

> **인증에 따른 제한.** 인증 전에는 홈 · 탐방 목록 둘러보기만 된다. 고교생은 재학 인증 승인과 보호자 동의가 모두 끝나야 탐방 신청(A-01), 대학생은 재학 인증 승인 뒤 탐방 개설(T-03), 사장님은 사업자 인증 뒤 가게 연결(S-01)이 가능하다. 운영자는 가입하지 않고 시드 계정으로 넣는다.

| 기능 ID | 기능명 | 역할 | 입력 | 처리 · 규칙 | 출력 | 예외 | 화면 |
|---|---|---|---|---|---|---|---|
| T-01 | 진로 문장으로 탐방 추천 (AI) | 고교생 | 하고 싶은 것 (문장), 관심 학과, 학교 · 날짜 (선택) | LLM이 문장에서 학과 · 관심 키워드 추출 → 모집중 탐방의 학과 · 소개와 비교해 정렬, 탐방별 추천 이유 한 줄 생성 | 탐방 목록 + 추천 이유 | 0건 → 같은 학교 모집중 탐방 | 홈, 추천 탐방 목록 |
| T-02 | 탐방 상세 조회 | 고교생 | 탐방 ID | 남은 자리 = 정원 − 승인 수, 내 신청 여부 · 가이드 인증 배지 포함, 오픈채팅 링크는 승인된 신청자에게만 | 탐방 정보, 가이드 프로필, 남은 자리, 내 신청 상태 | 없는 탐방 | 탐방 상세 |

## 구현 중 정할 것 (원문)

- 학교별 방학 기간 값 (T-03 날짜 검증, D-01)
- 쿠폰 유효기간을 '탐방 당일'로 둘지 (S-04) → 탐방당일로 하면 좋을듯
- 코스 후보 · 주변 상점 반경 (C-01, S-02)
- 강남대 · 경희대 · 명지대를 캠퍼스 반경으로 다시 봤을 때 방학 효과가 나오는지 (D-02, D-03, 발표)
- 착한가격업소 데이터가 5개교 주변을 덮는지 (D-03)
- 보호자 동의를 이메일 링크로 할지, 문자로 할지 (U-06)
- 국세청 사업자등록 진위확인 API 키 발급과 데모용 사업자번호 (U-07) → 지금 단계에 꼭 필요할지
- 시연에서 운영자 심사를 보여 줄지, 미리 승인된 계정으로 건너뛸지 (U-08)

개발 일정에 따라 일부 기능을 제외하고, 코스 초안 추천 기준을 고교생이 작성한 내용 중심으로 변경했다.

### C-01 AI 코스 초안 생성
- 변경 전: 승인된 신청자들의 하고 싶은 것을 모음 → 캠퍼스 주변 상점 중 우선순위 점수(D-03) 상위 후보, 제휴 상점 우선 → LLM이 2~3시간 코스(점심 · 카페 · 놀거리)와 지점별 추천 이유 작성
- 변경 후: 승인된 신청자들이 작성한 '하고 싶은 것'만을 추천 기준으로 사용 → 해당 내용과 관련 있는 캠퍼스 주변 상점을 후보로 골라 → LLM이 2~3시간 코스(점심 · 카페 · 놀거리)와 지점별 추천 이유 작성
- 변경 핵심
  - 상점 우선순위 점수와 제휴 여부를 코스 추천 기준에서 제외했다.
  - 승인된 고교생이 작성한 '하고 싶은 것'을 기준으로 주변 상점을 연결해 코스를 제안한다.

### 함께 반영한 기능 제외·수정
- 기능 명세에서 D-02 상점 우선순위 점수 계산 기능을 삭제했다.
- 유저 플로우에서 F-O2 사장님 리포트·빈 시간 달력 흐름을 목차와 본문에서 삭제했다.
- F-G2의 코스 초안 생성 단계도 고교생이 작성한 내용만을 추천 기준으로 삼도록 수정했다.

### 확인할 점
S-03에는 제휴 상점이 C-01 후보에서 우선된다는 문구가 남아 있다. 코스 추천은 고교생 작성 내용만을 기준으로 한다는 변경과 충돌할 수 있으므로, 제휴 여부를 추천 기준에서 제외할지 별도로 정리해야 한다.
