# 방학 상권 캠퍼스 탐방

방학 동안 대학 캠퍼스 주변 상권을 학생이 가이드와 함께 탐방하고, 코스 안의 제휴 상점에서 쿠폰을 쓰는 모바일 우선 웹 앱의 프런트엔드입니다.

React 19 · Vite · TypeScript SPA입니다. 백엔드 없이도 돌도록 목업(MSW)이 먼저이고, 폭 480px 이상 화면에서는 가운데 폰 프레임(390px) 안에 그립니다.

## 시작하기

```bash
npm install
cp .env.example .env.local   # 목업 모드 · 시연 도구 켬
npm run dev                  # http://localhost:5173
```

## 명령어

| 명령                                                    | 하는 일                                               |
| ------------------------------------------------------- | ----------------------------------------------------- |
| `npm run dev`                                           | 개발 서버(5173). `/api`는 `DEV_API_TARGET`으로 프록시 |
| `npm run build`                                         | 타입 검사 + 프로덕션 빌드(`dist/`)                    |
| `npm run preview`                                       | 빌드 결과를 4173에서 띄움                             |
| `npm run test` · `npm run test:run`                     | Vitest 감시 모드 · 한 번 실행                         |
| `npm run typecheck` · `npm run lint` · `npm run format` | 타입 검사 · ESLint · Prettier 쓰기                    |
| `npm run e2e`                                           | Playwright E2E(아래)                                  |

커밋 · 푸시 전 확인: `npm run test:run && npm run typecheck && npm run lint && npm run build`. CI도 main 푸시마다 같은 검사를 돈다. E2E는 체크포인트마다 직접 돌린다.

## E2E

```bash
npx playwright install chromium   # 처음 한 번
npm run e2e
```

`npm run e2e`는 `VITE_*`를 고정한 프로덕션 빌드(목업 모드 · 시연 도구 켬, `playwright.config.ts`)를 `vite preview`로 띄우고 아래 스펙을 돈다.

- `e2e/smoke.spec.ts`: 로그인 후 딥링크(`/my-tours`)를 새로고침해도 로그인 · 목업 데이터가 남는다.
- `e2e/golden-path.spec.ts`: 시연 골든 패스 전체. 고교생 희망 사항 등록 · 탐방 찾기 · 신청 → 가이드 승인(가이드 첫 화면 `/guide`) · AI 코스 완성 · 순서 변경 · 확정 → 고교생 코스 · 쿠폰 → 사장님 사용 처리. 전체 시연 패널로 한 번, 무대 링크의 발표 모드(`present=1`)에서 세로 막대의 역할 버튼만으로 한 번 돈다. 발표 모드에서는 역할 배지가 16px 이상이고 화면 제목(h1) 글자를 덮지 않는지도 본다.
- `e2e/demo-tools.spec.ts`: 발표 모드 역할 배지(와 좁은 화면의 시연 패널 토글)가 사장님 내 가게(`/owner/store`) 오른쪽 위 `로그아웃`을 덮지 않는지 상자 겹침으로 본다.
- `e2e/stage-viewport.spec.ts`: 무대 노트북 화면(브라우저 UI를 뺀 페이지 영역 1366×620 · 1280×600 · 1280×590 @1.5배)에서 탐방 찾기 결과의 희망 원문 카드 · 첫 탐방 행, 코스 완성 지점 3곳, 쿠폰 코드가 스크롤 없이 하단 탭 위에 보이는지 보고 사용 · 여유 높이를 테스트 기록(`stage-measure`)에 남긴다. 스크린샷은 `test-results/stage-{폭}x{높이}@{배율}x-{1~3}.png`.
- `e2e/review-loop.spec.ts`: 쿠폰 사용 → 방문 리뷰 쓰기 → 상점 시트의 새 AI 요약 → 사장님 리포트.
- `e2e/verify.spec.ts`: 재학 인증 사진 업로드와 같은 탭 보호자 동의 · `동의 완료로 건너뛰기`가 새로고침 없이 반영되는지.
- `e2e/p1-smoke.spec.ts`: 역할마다 P1 화면을 앱 안 링크로 열어 `곧 열려요.` 자리 화면이 없는지(자리 화면은 `/explore`뿐), 그리고 사장님 온보딩(사업자 인증 → 가게 연결 → 제휴 저장)을 처음부터 끝까지.
- `e2e/real-smoke.spec.ts`: 실서버 스모크(쓰기 없음). `E2E_REAL=1`일 때만 돌고 아니면 건너뛴다. 목업 빌드의 `/api`는 실서버가 아니므로 `E2E_BASE_URL`로 실서버에 닿는 배포를 가리킨다. 예: `E2E_REAL=1 E2E_BASE_URL=https://<배포 주소> npm run e2e -- e2e/real-smoke.spec.ts` (`E2E_BASE_URL`을 주면 목업 빌드를 띄우지 않는다). 이 대상은 `real-smoke` 전용이고, 시연 도구가 켜진 배포여야 한다(다른 E2E는 목업 빌드로 돈다).

사장님은 하단 탭 `내 가게`(`/owner/store`) · `쿠폰`(`/owner/coupons/redeem`) 두 개이고 MY 탭이 없어 로그아웃은 내 가게 오른쪽 위에 있다. 가이드는 로그인하면 `/guide`(내 탐방)에서 시작한다.

골든 패스와 무대 점검은 페이지 오류나 실패한 `/api/` 요청이 하나라도 있으면 실패한다. 4173에 이미 떠 있는 서버가 있으면 그 서버를 그대로 쓰므로, 다른 설정으로 띄운 서버는 먼저 끈다.

## 환경변수

`.env.example`을 `.env.local`로 복사해 쓴다. `VITE_*` 값은 빌드에 들어가 브라우저에 노출된다. 테스트는 값을 고정해 개발자의 `.env.local`이 섞이지 않게 한다. Vitest는 커밋된 `.env.test`, E2E는 `playwright.config.ts`의 `webServer.env`를 쓴다.

| 이름                 | 뜻                                                                                                                                                                            | 기본값                  |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| `VITE_API_BASE_URL`  | API 기본 경로                                                                                                                                                                 | `/api`                  |
| `VITE_API_MODE`      | `mock`(MSW 목업) · `real`(실서버). 주소 `?mode=`와 시연 패널 설정이 이 값보다 먼저다                                                                                          | `mock`                  |
| `VITE_MOCK_DOMAINS`  | 목업 모드에서 목업으로 받을 도메인. 쉼표로 나열한다(`auth`, `campuses`, `tours`, `applications`, `courses`, `coupons`, `demo` 등). 빠진 도메인은 `/api`로 실서버에 간다(아래) | `all`                   |
| `VITE_DEMO_TOOLS`    | `true`면 시연 패널을 항상 보인다. 아니어도 `?demo=1`로 켤 수 있다                                                                                                             | `false`                 |
| `VITE_KAKAO_MAP_KEY` | 카카오맵 JavaScript 키. 비어 있으면 도식 지도로 그린다(결정 0004)                                                                                                             | 없음                    |
| `VITE_DEMO_PASSWORD` | 실서버 시연 계정 비밀번호(빠른 로그인용). 목업은 시드 비밀번호 `demo1234`를 쓴다                                                                                              | `demo1234`              |
| `DEV_API_TARGET`     | `npm run dev`가 `/api`를 보낼 백엔드 주소. 번들에는 들어가지 않는다                                                                                                           | `http://localhost:8080` |

`/api`가 실서버에 닿는 길: `npm run dev`는 Vite 프록시(`DEV_API_TARGET`)로 보낸다. 배포의 `/api` 프록시(`vercel.json` rewrite, 결정 0005)는 아직 없고, 백엔드 배포 주소가 정해지면 넣는다(팀 요청 13, MVP 3단계).

- `123-45-67890`(정해린 · 2021-03-02): 일치. 인증되고 가게 찾기로 간다(상호 검색 — 예: `일삼일구`, 단국대 근처의 연결 전 카페). 사업자 인증 화면의 `시연 사업자 정보 채우기`가 이 값을 채운다(시연 도구가 켜졌을 때)
- `111-11-11111`: 번호는 등록돼 있지만 대표자명 · 개업일이 다르게 등록돼 있어 불일치 오류
- `999-99-99999`: 폐업 번호(번호만 본다)

시연 패널의 `P1 계정` 선택 + `이 계정으로 전환`으로 위 P1 상태 계정(인증 전 · 심사 중 · 반려 · 동의 대기 · 동의 만료 · 사업자 인증 전 · 가게 연결 전)으로 바로 바꾼다. 동의 대기인 고교생의 `/verify/guardian`에는 시연 도구가 켜졌을 때 `보호자 페이지 열기`와 `동의 완료로 건너뛰기`(시연 동의 건너뛰기)가 보인다 — 실서버에서는 보이지 않는다.

목업 업로드 사진은 새로고침하면 사라진다. 시드 계정의 견본 학생증(`public/mock-docs`)만 그대로 남는다.

목업 상점 590곳은 소상공인시장진흥공단 상가(상권)정보(공공데이터포털 15083033, 2026-09 기준)에서 다섯 캠퍼스 반경 1km 안의 용인시 음식점(주점 제외)을 거른 실제 가게다. 상호 · 업종 · 주소 · 좌표만 실데이터이고 제휴 · 쿠폰 · 리뷰 · AI 요약 · 사장님 계정은 시연 값이다. 출처 · 거른 조건 · 업종 대응 · 다시 만드는 법(`scripts/build-yongin-stores.mjs`)은 [`docs/reference/store-data.md`](docs/reference/store-data.md).

시연 패널(폭 900px 이상이면 프레임 옆, 좁으면 오른쪽 위 버튼)에서 역할을 바로 바꾸고, `쿠폰 가게 사장님으로 전환`으로 학생이 마지막으로 본 쿠폰의 가게 사장님이 되어 그 코드를 사용 처리 화면에 채운다. 사용 처리 화면의 `최근 쿠폰 채우기`는 그 쿠폰이 내 가게 쿠폰일 때만 보인다.

발표 모드(`present=1`)에서는 패널이 역할 버튼 4개만 남은 세로 막대로 줄어든다. 이때 `사장님`이 위의 전환을 대신한다. 학생이 마지막으로 본 쿠폰이 있으면 그 쿠폰 가게의 사장님으로 바꾸고 사용 처리 화면에 코드를 채우며, 없으면 `owner1`로 들어간다. 막대 아래에는 지금 API 모드(`목업` · `실서버`)가 늘 보이고, AI 속도 `느리게`나 지도 `도식`이 켜져 있으면 그것도 보인다. 시연 데이터를 초기화하면 최근 쿠폰도 지워진다.

목업 모드에서는 브라우저 탭마다 데이터를 따로 들고 있다. 목업 DB는 탭의 메모리에서 돌고, 브라우저 저장소는 마지막에 쓴 탭이 덮어쓴다. 그래서 목업 시연은 브라우저 하나에 탭 하나로 하고, 역할은 시연 패널로 바꾼다. 학생 쿠폰 화면이 사장님의 사용 처리를 5초 안에 반영하는 것을 두 탭(또는 두 기기)에 나란히 띄워 보여 주려면 실서버 모드여야 한다.

## 원클릭 시연 링크

주소 하나로 시연 준비를 끝낸다. 초기화와 로그인은 첫 화면이 그려지기 전에 끝나고, 처리한 파라미터는 주소에서 지운다(`present`만 남긴다). 무대 링크는 `mode=`를 늘 적는다. 지난 리허설에서 저장한 API 모드가 남아 있어도 링크가 다시 정한다.

- 처음부터(목업): `/?demo=1&mode=mock&reset=1&as=student&present=1`
- 코스 확정 단계부터(목업, 쿠폰 화면 바로 시연): `/?demo=1&mode=mock&reset=1&checkpoint=CONFIRMED&as=student&present=1`
- 처음부터(실서버): `/?demo=1&mode=real&key=<초기화 키>&reset=1&as=student&present=1`
- 발표 모드 끄기: `/?present=0`

| 파라미터     | 값                                             | 동작                                                                                                                                                                          |
| ------------ | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `demo`       | `1`                                            | 시연 도구(시연 패널)를 켠다(브라우저에 저장)                                                                                                                                  |
| `reset`      | `1`                                            | 시연 데이터 초기화. 목업은 오늘 날짜 기준 시드로 되돌리고, 실서버는 백엔드 시연 리셋을 부른다. 로그인과 최근 쿠폰도 지우고, AI 속도 · 지도를 기본값(보통 · 자동)으로 되돌린다 |
| `checkpoint` | `START` · `APPLIED` · `APPROVED` · `CONFIRMED` | `reset`과 함께 쓴다. 골든 패스를 그 단계(처음 · 신청 · 승인 · 코스 확정)까지 진행한 데이터                                                                                    |
| `as`         | `student` · `guide` · `owner` · `admin`        | 그 역할의 시연 계정으로 빠른 로그인                                                                                                                                           |
| `present`    | `1` · `0`                                      | 발표 모드 켜기 · 끄기. 시연 패널이 역할 버튼 막대로 줄고 프레임에 역할 배지가 뜬다                                                                                            |
| `mode`       | `mock` · `real`                                | API 모드. `demo=1`과 함께면 브라우저에 저장해 다시 바꿀 때까지 유지하고, 없으면 이번 한 번만 쓴다                                                                             |
| `key`        | 문자열                                         | 실서버 초기화 키(헤더 `X-Demo-Key`)                                                                                                                                           |
