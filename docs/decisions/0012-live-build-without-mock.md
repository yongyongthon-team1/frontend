# 0012. 라이브 배포는 목업을 뺀 빌드로, 목업은 로컬 · 별도 경로에서만

- 날짜: 2026-11-10

## 맥락

배포본은 목업(MSW) 모드가 기본이었고 시연 패널 · `?mode=`로 실서버와 오갔다(결정 0002). 본선 심사위원이 라이브 링크에서 목업 모드나 모드 전환을 보면 "실제로 동작하는 서비스가 아니다"로 읽힐 수 있다. 목업 모드의 AI도 규칙 흉내라서, 그 화면으로 시연하면 수상 요건(AI 핵심 기능)까지 흔들린다.

## 결정

빌드 상수 `__MOCK_API__`(`vite.config.ts`의 `define`)로 목업을 번들에 넣을지 정한다. `VITE_MOCK_API`가 `on`이면 넣고 `off`면 빼며, 비어 있으면 Vercel 프로덕션 빌드(`VERCEL_ENV=production`)만 뺀다.

뺀 빌드는:

- `main.tsx`의 목업 분기와 동적 import가 지워져 MSW · 핸들러 · 시드가 번들에 없다. public의 `mockServiceWorker.js` · `mock-docs`도 배포 폴더에서 지운다.
- 늘 실서버다 — `?mode=mock`, 시연 패널 저장값, `VITE_API_MODE`를 무시한다(`resolveApiMode`).
- 시연 패널에 API 모드 전환 · 목업 AI 속도 · `실서버` 표시가 없다. 문구도 같은 상수로 묶어 번들에서 빠진다.
- 예전 목업 배포를 연 브라우저에 남은 MSW 서비스 워커를 부팅 때 해제한다.

목업은 로컬(`npm run dev` · `npm run preview`)과 E2E에서 쓰고, 링크가 필요하면 Vercel 미리보기 배포나 `VITE_MOCK_API=on`을 준 별도 프로젝트로 띄운다.

## 결과

라이브 링크는 백엔드 상태를 그대로 보인다 — 백엔드 데이터가 비면 화면도 빈다(11/10 `GET /campuses`가 빈 목록). 그래서 이 빌드의 프로덕션 배포는 백엔드 시드가 들어온 뒤에 한다. 무대에서 백엔드가 죽으면 대체 경로(목업 링크 또는 녹화본)가 필요하다 — 팀 요청 17(비상용 녹화본)과 함께 정한다. `VITE_REAL_API=off`(실서버 잠금)와 함께 주면 둘이 부딪히는데, 목업 코드가 없으므로 실서버가 이긴다.
