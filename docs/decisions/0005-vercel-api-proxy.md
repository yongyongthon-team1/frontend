# 0005. Vercel `/api` 프록시 rewrite로 백엔드를 부른다

- 날짜: 2026-11-03

## 맥락

프론트는 Vercel에 배포하고 백엔드는 별도 서버다. 브라우저가 백엔드를 직접 부르면 CORS와 HTTPS 혼합 콘텐츠 문제가 생길 수 있고, 백엔드 주소가 바뀌면 프론트를 다시 빌드해야 한다.

## 결정

Vercel에서 SPA 새로고침용 rewrite와 함께 `/api/*`를 백엔드 주소로 보내는 rewrite(프록시)를 둔다. 프론트의 기본 `VITE_API_BASE_URL`은 `/api`다. 로컬에서는 Vite dev 서버 프록시로 같은 구조를 만든다. 백엔드 주소는 11/12까지 고정 도메인(또는 고정 IP)으로 확정해 달라고 팀에 요청하고, 그 뒤로 바꾸지 않는다.

## 결과

브라우저에서는 같은 출처 요청이라 CORS와 혼합 콘텐츠를 피한다. 11/4 빈 앱 배포 체크포인트에서 프록시 동작을 먼저 확인한다. main 푸시가 곧 프로덕션 배포이므로 로컬 검사를 통과한 커밋만 푸시한다.

11/7 백엔드 경로에는 접두사가 없다 — 프록시가 `/api`를 뗀다(2C-R1). Vercel rewrite는 주소가 정해지면 SPA 규칙 앞에 둔다.
