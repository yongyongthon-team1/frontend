# 0002. MSW 목업으로 먼저 개발하고 도메인 단위로 실서버로 교체한다

- 날짜: 2026-11-03

## 맥락

백엔드 API 명세는 ERD를 바탕으로 따로 나오고 있어서 프론트 개발 시작 시점에는 없다. 명세를 기다리면 11/8 MVP와 11/10 실서버 골든 패스 체크포인트를 맞출 수 없다. 반대로 목업을 섞어 쓰면 ID와 상태가 어긋나 원인 모를 버그가 난다.

## 결정

명세 전에는 MSW 2 목업으로 개발한다. 데이터 모양과 상태값은 ERD를 그대로 따르고(`RECRUITING`, `PENDING`, `ISSUED` …), 목업 DB는 인메모리로 두되 localStorage에 버전 키로 저장해 새로고침 후에도 이어지게 한다. 명세가 오면 시연 대본 순서대로 도메인 하나씩 실서버로 교체하고 `VITE_MOCK_DOMAINS`로 도메인 단위 목업을 켠다. 단 시연과 리허설은 "전부 목업" 또는 "전부 실서버"로만 한다. 섞지 않는다.

## 결과

백엔드가 늦어도 화면 개발이 멈추지 않고, 목업 핸들러가 곧 프론트가 기대하는 API 계약 초안(`docs/api/frontend-needs.md`)이 된다. 연동할 때마다 대시보드의 API 연동표를 갱신한다. 업무 규칙의 최종 기준은 백엔드 API이므로, 명세가 오면 목업 규칙을 백엔드 동작에 맞춘다.
